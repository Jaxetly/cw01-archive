# Контрольная № 1. Система архивирования

Инфраструктура хранит задания в Yandex Message Queue, ZIP-архивы в закрытом Object Storage и сведения об архивах в документной таблице YDB. На первом этапе конфигурация поднимает очередь заданий, очередь необработанных сообщений, бакет, базу с таблицей `archives` и служебный аккаунт для управления очередями. Облачная функция, триггер и API-шлюз относятся к следующему этапу.

[Условие контрольной](https://docs.itiscl.ru/vvot/2026-2027/cw/cw01/)

## Развёртывание инфраструктуры

Нужны Terraform 1.6 или новее, Python 3, настроенный `yc` и права на создание ресурсов и назначение ролей в учебном каталоге. Выполняйте команды из корня репозитория в Bash или Zsh. Подставьте свои три значения. Имя бакета должно быть глобально уникальным, начинаться с `vvotNN-` и принадлежать новому стенду. Оно также определяет префикс остальных ресурсов.

| Параметр | Назначение |
|---|---|
| `cloud_id` | Идентификатор облака, в котором находится каталог |
| `folder_id` | Идентификатор каталога, в котором будут созданы ресурсы |
| `bucket_name` | Имя нового закрытого бакета для ZIP-архивов |
| `YC_TOKEN` | Временный токен вызывающего пользователя. Yandex-провайдер и Document API читают его из окружения |

```sh
export TF_VAR_cloud_id="<id облака>"
export TF_VAR_folder_id="<id каталога>"
export TF_VAR_bucket_name="vvot00-archive-example"

YC_TOKEN="$(yc iam create-token)" && export YC_TOKEN
```

```sh
umask 077
state_dir="${XDG_STATE_HOME:-$HOME/.local/state}/cw01-archive/$TF_VAR_bucket_name"
mkdir -p "$state_dir"
state_file="$state_dir/terraform.tfstate"

terraform -chdir=terraform init
terraform -chdir=terraform fmt -check
terraform -chdir=terraform validate
terraform -chdir=terraform plan -state="$state_file"
terraform -chdir=terraform apply -state="$state_file"
```

Message Queue требует подпись запросов статическим ключом. Terraform создаёт отдельный сервисный аккаунт с ролью `ymq.admin` в выбранном каталоге и выпускает для него ключ. Пользователь вводит только `YC_TOKEN`. Секретная часть ключа хранится в приватном файле состояния и его резервной копии, поэтому все команды, которые работают с состоянием, используют один и тот же путь вне репозитория. Для документной таблицы Terraform вызывает Document API с IAM-токеном и проверяет строковый первичный ключ `key`.

Основная очередь хранит задания сутки. `visibility_timeout_seconds = 900` на время обработки скрывает взятое задание от других получателей, а `receive_wait_time_seconds = 20` задаёт ожидание новых заданий при чтении пустой очереди. `redrive_policy` направляет сообщение после первой неудачной попытки в DLQ, где оно хранится 14 суток. В YDB задан лимит 10 единиц работы запросов в секунду и 1 ГБ данных. Закрытый бакет вмещает до 10 ГиБ архивов.

## Проверка и удаление стенда

```sh
python3 scripts/check_bucket.py "$TF_VAR_bucket_name"
terraform -chdir=terraform destroy -state="$state_file"
terraform -chdir=terraform state list -state="$state_file"
unset YC_TOKEN
```

Проверка загружает маленький ZIP, скачивает его с IAM-токеном, сверяет содержимое и проверяет анонимный `403`. Тестовый ZIP остаётся в бакете. При `destroy` параметр `force_destroy` удаляет объекты бакета, поэтому для стенда нужно отдельное новое имя. После успешного удаления список ресурсов в state пуст. Файлы состояния и резервную копию можно удалить после проверки.
