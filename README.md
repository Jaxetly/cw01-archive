# Контрольная № 1. Система архивирования

Система получает имя и публичный URL файла, создаёт ZIP и сохраняет его в закрытом Object Storage. Клиент получает список архивов и скачивает ZIP через служебный домен API Gateway.

[Условие контрольной](https://docs.itiscl.ru/vvot/2026-2027/cw/cw01/)

## Путь задания

| Запрос | Что происходит |
|---|---|
| `POST /tasks` | Шлюз проверяет JSON с `name` и `url`. Корректное задание попадает в Yandex Message Queue, и клиент получает `202`. Ошибка валидации даёт `400` |
| `GET /archives` | Шлюз выполняет `Scan` таблицы `archives` и возвращает массив записей с `name`, `url` и `key` |
| `GET /archives/{key}` | Шлюз читает одну запись через `GetItem`. Если записи нет, клиент получает `404` |
| `GET /download/{key}` | Шлюз читает ZIP из закрытого бакета от своего сервисного аккаунта. Если объекта нет, клиент получает `404` |

Триггер передаёт функции одно сообщение. Функция скачивает файл, помещает его в ZIP с именем из задания, загружает ZIP под ключом `<uuid_v7>.zip` и только после этого записывает метаданные в YDB. При повторной доставке того же сообщения ключ остаётся прежним. При успешном вызове триггер удаляет сообщение. При ошибке функция завершает вызов с исключением, и основная очередь направляет задание в DLQ после первой неудачной попытки.

Функция проверяет, что HTTP(S)-адрес публичный, перед каждым подключением, включая перенаправления. Загрузка ограничена 90 секундами и 32 МиБ. Сформированный ZIP должен укладываться в лимит ответа шлюза 2,5 МБ.

## Развёртывание инфраструктуры

Нужны Terraform версии 1.x начиная с 1.6, Python 3.8 или новее для служебных скриптов и настроенный `yc`. Аккаунту Yandex Cloud нужны права создавать ресурсы, назначать роли и использовать сервисные аккаунты в выбранном каталоге. Облачная функция запускается в среде Python 3.14.

Если CLI ещё не настроен, запустите `yc init` и выберите своё облако и каталог. Команды ниже выполняйте из корня репозитория в Bash или Zsh. Первые две команды берут идентификаторы из текущего профиля `yc`. В имени бакета замените `00` на двузначный номер своего каталога. Имя должно быть глобально уникальным и определяет префикс остальных ресурсов. [Настройка `yc`](https://yandex.cloud/ru/docs/cli/quickstart)

| Параметр | Назначение |
|---|---|
| `cloud_id` | Идентификатор облака, в котором находится каталог |
| `folder_id` | Идентификатор каталога, в котором будут созданы ресурсы |
| `bucket_name` | Имя нового закрытого бакета для ZIP-архивов |
| `YC_TOKEN` | Временный токен вызывающего пользователя. Yandex-провайдер и Document API читают его из окружения |

```sh
export TF_VAR_cloud_id="$(yc config get cloud-id)"
export TF_VAR_folder_id="$(yc config get folder-id)"
export TF_VAR_bucket_name="vvot00-archive-$(date +%s)"

YC_TOKEN="$(yc iam create-token)" && export YC_TOKEN
```

```sh
umask 077
state_dir="${XDG_STATE_HOME:-$HOME/.local/state}/cw01-archive/$TF_VAR_bucket_name"
mkdir -p "$state_dir"
state_file="$state_dir/terraform.tfstate"

terraform -chdir=terraform init
```

Если провайдер не скачивается напрямую из Terraform Registry, повторите `init` через официальное зеркало Yandex Cloud. Файл настроек используется только для этой команды. [Установка провайдера через зеркало](https://yandex.cloud/ru/docs/ydb/terraform/install) · [Настройки Terraform CLI](https://developer.hashicorp.com/terraform/cli/config/config-file)

```sh
cat > "$state_dir/providers.tfrc" <<'EOF'
provider_installation {
  network_mirror {
    url     = "https://terraform-mirror.yandexcloud.net/"
    include = ["registry.terraform.io/yandex-cloud/yandex"]
  }
  direct {
    exclude = ["registry.terraform.io/yandex-cloud/yandex"]
  }
}
EOF
TF_CLI_CONFIG_FILE="$state_dir/providers.tfrc" terraform -chdir=terraform init
```

```sh
terraform -chdir=terraform fmt -check
terraform -chdir=terraform validate
terraform -chdir=terraform plan -state="$state_file"
terraform -chdir=terraform apply -state="$state_file"
```

Перед `apply` проверьте, что план относится к новому бакету и выбранному каталогу. Terraform собирает ZIP с исходниками функции, создаёт документную таблицу через Document API и проверяет её строковый ключ `key`. Служебный HTTPS-адрес шлюза появляется в выходном значении `gateway_url`.

### Кто к чему имеет доступ

- Terraform создаёт отдельный аккаунт с `ymq.admin` на указанный каталог и выпускает ему ключ для подписания запросов создания, настройки и удаления очередей. Секретная часть хранится в приватном файле состояния и его резервной копии. Все команды, работающие с состоянием, используют один и тот же путь вне репозитория.
- Шлюз использует `ymq.writer` для постановки задач. `ydb.viewer` на базе и `storage.viewer` на бакете дают ему доступ к результатам.
- Триггер читает очередь с `ymq.reader` и вызывает функцию архивирования с `functions.functionInvoker`.
- Функция получает короткоживущий IAM-токен своего аккаунта при вызове. `storage.uploader` разрешает загрузить ZIP в бакет проекта, а `ydb.editor` на базе проекта — записать метаданные.

### Параметры ресурсов

| Ресурс | Настройка и её смысл |
|---|---|
| Основная очередь | Видимость **900 с** скрывает взятое сообщение на время обработки. Long polling **20 с** задаёт максимальное ожидание новых сообщений при чтении пустой очереди. Хранение **1 сутки**, `maxReceiveCount = 1` направляет необработанное сообщение в DLQ после первой попытки |
| DLQ | Хранит ошибочные задания **14 суток** |
| Триггер | Размер группы **1**, ожидание группы **0 с**. Сообщение сразу передаётся функции |
| Функция | **256 МБ** памяти и **600 с** на вызов. Время вызова меньше таймаута видимости сообщения |
| YDB | Serverless для транзакционной нагрузки, лимит **10 RU/с** и **1 ГБ** данных. `archives` — документная таблица |
| Object Storage | Приватный бакет объёмом до **10 ГиБ** на все архивы |

## Проверка и удаление стенда

```sh
gateway_url="$(terraform -chdir=terraform output -state="$state_file" -raw gateway_url)"
python3 scripts/check_api.py "$gateway_url"
```

Скрипт проверяет `400` для некорректного задания и `404` для отсутствующего архива. Затем он отправляет задачу, ждёт запись в YDB, открывает карточку, скачивает ZIP и сравнивает его содержимое с исходными байтами. Можно передать свой небольшой публичный файл через `--source-url`. При первом запуске триггер может начать обработку в течение пяти минут после создания. Если проверка завершилась по таймауту ожидания записи, повторите её после запуска триггера. [Запуск триггера](https://yandex.cloud/ru/docs/functions/operations/trigger/ymq-trigger-create)

Для проверки DLQ отправьте отдельное задание с недоступным источником. В консоли Yandex Cloud откройте выбранный каталог → **Message Queue** и проверьте колонку **Сообщений в очереди** у очереди с суффиксом `-dlq`. С таймаутом видимости **900 с** перенос может занять около 15 минут. [Просмотр количества сообщений](https://yandex.cloud/ru/docs/message-queue/operations/message-queue-receive-and-delete-message)

```sh
curl -i -X POST "$gateway_url/tasks" -H 'Content-Type: application/json' \
  -d '{"name":"missing.txt","url":"https://httpbin.org/status/404"}'
```

Для удаления используйте те же входные значения и тот же `state_file`. Если IAM-токен устарел, получите свежий командой `YC_TOKEN="$(yc iam create-token)" && export YC_TOKEN`. Параметр `force_destroy` позволяет удалить выделенный стенд вместе со всеми объектами созданного бакета. После удаления список ресурсов в state должен быть пуст.

```sh
terraform -chdir=terraform destroy -state="$state_file"
terraform -chdir=terraform state list -state="$state_file"
unset YC_TOKEN
```
